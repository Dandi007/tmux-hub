# Preserve alternate screen across ordinary snapshots

## 1. User behavior and constraints
Reconnecting to a running full-screen application must keep its alternate screen active: wheel navigation must not reveal normal-screen history. Exiting the application must restore the saved normal screen, history and cursor. Desktop and phone must behave the same, including a broadcaster started after the application entered alternate mode. Keep explicit normal-history navigation and following behavior intact.

## 2. Current behavior and root cause
Deployed e07e0c8 reproduces on desktop and phone: tmux alternate_on=1, but after ordinary capture-pane replay wheel navigation changes linesFromBottom from 0 to 25 and displays prior history. captureSnapshot emits RIS, history and active screen text without entering alternate mode. The emulator fallback serializes this mode, but the ordinary path does not. ModeShadow alone cannot solve cold attach after startup because it has not necessarily observed the entry sequence. The separate weak-background obsolete-history failure remains under investigation; no common cause is assumed.

## 3. Design
Read alternate_on and the saved normal cursor together with pane geometry inside the existing alignment window. When alternate is active, capture the saved normal screen with tmux capture-pane -a, build its history and visible grid, position its saved cursor, then enter alternate mode before painting the active capture and restoring modes/current cursor. Read history without -a: real tmux exposes normal history above the active grid, while -a exposes only the saved normal visible screen and has no history. Preserve the existing ordinary normal path and retry/overlap alignment. A failed saved-screen capture uses the existing logged emulator fallback; never force fallback to hide an ordinary-path defect. Tmux defers resizing its saved normal grid until alternate exit: after growing phone43→45rows, the saved capture still has the old grid. The new E2E actually failed the unchanged screen oracle by two rows after a real exit. Observe parsed live DECRST47/1047/1049 after emulator priming and emit an internal normal-screen event. Existing resync-capable WS consumers request their existing serialized repair, capturing tmux after its saved grid expands. This uses the ordinary authoritative capture (not emulator fallback), preserves the replay-done/scroll contract and is coalesced with resize/overlap repairs. No wire protocol change.

## Independent review refinements
The exit refresh expands RIS to ordinary app exit, so it must preserve the emulator's public application-cursor, keypad, bracketed-paste and mouse-reporting modes as well as ModeShadow's omitted modes. Verify real keyboard, clipboard paste and SGR mouse bytes received by an application after automatic exit repair. Cold unobserved input state is not established by this warm-mode fix and remains disclosed. A normal-screen repair must not wait indefinitely for 100ms quiet: add an urgent repair request to the same serialized chain, bounded by the existing100ms scheduling delay and5capture alignment attempts, coalescing resize/overlap requests. Existing busy-overlap quiet repair remains available afterward. Add continuous50ms localized output during exit; the screen must converge while output continues, before any stop file is created. The old64E2E/671unit green c64 evidence does not certify these later changes.

Refresh scope: deliver snapshot buffer metadata through an optional internal callback after final alignment, not every attempt. Each WS remembers whether its own latest snapshot was alternate. Only such a connection requests normal-exit repair; ordinary live enter/exit without a replay does not add a reset and preserves its original rendition. Emit metadata for fallback too from the emulator's active public buffer. Verify both ordinary-exit no-refresh and replayed-exit refresh controls with actual app input. This also avoids expanding known saved-SGR limitations to unaffected ordinary exits.

Platform input fixtures: desktop uses actual ArrowUp, browser clipboard Ctrl+Shift+V and mouse reporting bytes. Mobile deliberately attaches xterm readOnly:true; its valid control uses toolbar Up and the text composer (literal+Enter), and verifies terminal clicking sends no raw mouse bytes. Earlier mobile raw-xterm-input failure was an invalid fixture, not a product mode failure; its empty-byte evidence remains retained. Desktop old-code input evidence contains CSI[A plus unbracketed PASTE_CHECK. No test is skipped; both platform-specific paths run.

During final tolerated overlap, a normal-exit request can already have been parsed before the consumer learns its snapshot was alternate. Snapshot metadata includes whether such a request occurred since capture began; the WS schedules the same urgent repair after receiving that metadata. A controlled-runner alignment regression exhausts all5captures and verifies exit notification reaches the consumer exactly with the delivered snapshot.

Retried captures use exponential delay capped at1s, independent of a quiet window; generic busy-overlap repair retains its existing quiet behavior.
